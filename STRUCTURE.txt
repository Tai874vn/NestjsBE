JOBAURA BACKEND (NestJS): WHERE THINGS ARE
==========================================

HOW TO FIND THE CODE FOR SOMETHING YOU SEE ON THE WEBSITE
  1. Find the API call: browser DevTools (F12) > Network > click the action > the request URL,
     e.g. GET /api/hiring-posts?keyword=react. (Or read it in the frontend: src/shared/api/endpoints/.)
  2. Look that URL up in the API table at the end of this file: it gives the controller file:line and
     the service function it calls. Ctrl+click a function name in VS Code to jump to it (F12 = go to definition).
  3. Or search an @find tag in VS Code (Ctrl+Shift+F), the same words as the frontend:
       @find hiring-posts search        everything about that search box, frontend and backend
       @find hiring-posts search keyword-fields   the fields a keyword is searched in
       @find app request                  the steps every request goes through (security, sign-in, validation)
     or in the terminal: yarn find hiring-posts location

FOLDERS
  src/main.ts               starts the app: security headers, body size, cookies, CORS, validation
  src/app.module.ts         joins every module; registers the global guards, filter and interceptor
  src/config/               environment check (env.validation.ts), CORS and trusted origins
  src/common/               shared by many modules: guards, decorators, DTO helpers, error filter,
                            middleware, observability (request logs), constants, data (occupations.json)
  src/modules/<name>/       one module per part of the product (layout below)
  src/database/ prisma.service.ts   database connection (Prisma)
  prisma/schema.prisma      the database tables;  prisma/migrations/  every change to them
  src/seed, prisma/seed*.ts demo data;  src/tools/  one-off scripts;  scripts/dev/  local development

Every module has the same layout:
  src/modules/<name>/
    <name>.module.ts   lists the controllers and services of the module
    controllers/       the URLs (routes): read the request, call a service, return the answer
    dto/               the shape and rules of request input (class-validator): types, lengths, allowed values
    services/          the work: database queries and business rules
    utils/             plain functions without database or DI (search filters, checks, rules, labels)
    gateways/          WebSocket (real-time) handlers, where the module has them
  Tests live in a __tests__ folder next to the code they test (name.spec.ts).

WHAT HAPPENS TO ONE REQUEST (in this order)
  1. main.ts middleware: helmet (security headers), JSON body max 1 MB, cookies, Cache-Control
  2. global guards (app.module.ts): JwtAuthGuard (signed in? @Public() skips it), RolesGuard (@Roles),
     CsrfGuard (cookie requests must send the CSRF token from a trusted origin), HttpThrottlerGuard (rate limit)
     files: src/common/guards/
  3. ValidationPipe (src/main.ts:46): checks the DTO; unknown fields -> 400 (whitelist + forbidNonWhitelisted);
     values are converted and trimmed by @Transform rules (src/common/dto/string.transforms.ts)
  4. controller -> service -> Prisma (Prisma sends every value as a SQL parameter: no SQL injection)
  5. errors: src/common/errors/all-exceptions.filter.ts gives every error the same shape
     { statusCode, message, error, code?, requestId }; 5xx never shows internal details
